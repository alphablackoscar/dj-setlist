# cuetool — セットリストにメモリーＱを打つ

セットリストの曲にメモリーキューを打った rekordbox XML を作る。
音源を読む・ネットワークを使わない・依存ゼロ。

```
頭 / イントロ終 / 始まり / メイン → メイン2 → メイン3 … / メイン終 / アウトロ
```

**「メイン」は DJ 用語で曲が一番盛り上がる部分**（エネルギーが強く、歌が薄い）。
**「始まり」は曲の始まり = イントロの終わり**。2026-10-21 までこの 2 つを取り違えていた
（ユーザー指摘:「あなたは cue の打ち方を誤解している」）。

**盛り上がりの中は 8 小節ごとに刻む**（メイン2 / メイン3 …）。
「盛り上がりが 8 小節何個分か」を目で数えられるようにするため（ユーザー要求）。

本人の流儀の実測（189 曲 1512 個。`node scripts/cue/style.js`）:

| | |
|---|---|
| 1 曲に打つＱ | **中央値 8 個**（7-10 個で 85%） |
| 隣り合う間隔 | **50.2% がちょうど 8 小節** |
| 8 小節の連 | 1 曲あたり **2.02 本**（長さ 2 本 51% / 3 本 33% / 4 本 11%） |

→ **5 点では足りていなかった。** いまは 1 曲 5-9 個（53 曲のセットで中央値 7）。

## 使い方

```bash
# セットリスト（solver が out/ に書いた XML）にＱを打つ
node packages/cuetool/src/cli.js --setlist out/setlist_2026-10-17T04-46-33-454_2.xml

# 1 曲だけ試す
node packages/cuetool/src/cli.js --pick "lose your head"

# 画面（packages/app）が使う形
node packages/cuetool/src/cli.js --setlist <xml> --json
```

出力は `out/<もとの名前>_cue.xml`。アプリでは **「Ｑ 付きで書き出す」ボタン**から呼ぶ。

| フラグ | 既定 | |
|---|---|---|
| `--setlist <xml>` | — | solver が書いたセットリスト XML。かける順は PLAYLISTS が正本 |
| `--pick <語>` | — | 曲名・アーティストの部分一致。当たった曲**全部**に打つ（候補を表示する） |
| `--collection <xml>` | `data/collection.xml` | 曲の正本。**読むだけ** |
| `--db <path>` | `data/features.db` | `bpm_measured` を引く。無くても動く（倍/半分のグリッドは直らない） |
| `--json` | — | 標準出力に結果 JSON。画面が読む |

速さ: 全長デコード + 構造解析で **1 曲 0.3 秒**。26 曲で約 8 秒、53 曲で約 17 秒。

## 絶対に崩さない約束

1. **`data/collection.xml` に書かない。** 読み取り専用の資料として扱う（ユーザー指示 2026-10-17）。
   取り込みで事故っても元の XML が無傷なら rekordbox 側を作り直せる。
2. **既にＱがある曲には打たない。** `POSITION_MARK` が 1 つでもあれば触らない
   （ホットキューだけの曲も触らない側に倒す）。判定を人に任せず仕組みで担保する。
3. **Ｑを打った曲だけを XML に入れる**（ユーザー指示 2026-10-21）。
   打てなかった曲は XML に出てこない（理由は画面と標準出力に出す）。
   **曲の並びは `.m3u8`（普通の書き出し）が渡す**ので、この XML は**Ｑを配るためだけの道具**。
   旧ルール「曲がセットから消えてはいけない」は、普通の書き出しを m3u8 に分けた時点で用済み。
   帰結: **触る対象が減って安全**（53 曲のセットなら 47 曲だけが XML に入る）。
4. **こちらの値を 1 つも持ち込まない。** TRACK のかたまりを**そのまま写し**、
   `POSITION_MARK` を挿すだけ。`AverageBpm` も `<TEMPO>` も rekordbox 自身の値を書き戻す。
   → 取り込みでグリッドが動かない。詳しい理由は `src/xml.js` の頭を読むこと。
5. **`Type="0"` / `Num="-1"`**（メモリーキュー）。この組み合わせでゲートを通した。変えない。

## 取り込み方（2026-10-19 に実機で通したゲート）

1. rekordbox の「読み込み用ライブラリ」にこの XML を指定する（**設定は 1 回だけ**。
   以後は中身を上書きしてツリーを読み直す）
2. ツリーから曲を取り込む
3. 既存曲は **「この楽曲は現在のコレクションに既に含まれています。…タグ情報を読み込みますか？」**
   → **「はい」でＱがマージされる**
4. 同じダイアログに「解析ロックされている楽曲の拍位置情報とキー情報は読み込みません」。
   **ロックが安全弁。** ロックしていない曲は拍位置とキーが上書きされうる（この XML は
   元の値を書き戻すので値は変わらないが、ロックしておく方が安全）

## 当たり具合（189 曲の手打ちＱで実測。2026-10-21）

**出すＱの数が曲ごとに変わるので、点ごとの一致だけでは足りない。** この 2 つが本命:

| | |
|---|---|
| **カバー率 34%** | 本人のＱ 1269 個のうち 430 個に当たっている（取りこぼしの少なさ） |
| **的中率 41%** | こちらのＱ 1011 個のうち 412 個が本人のＱの上（余計に打っていないか） |

片方だけ見ると「全部の 8 小節線に打てばカバー率 100%」「1 本だけ打てば的中率 100%」で
騙せる。**必ず両方見ること。**

点ごと（±2 小節で一致）: イントロ終 59% / 始まり 53% / メイン 42% / メイン終 28% / アウトロ 33%。

**アウトロとメイン終は目で直す前提。** 直す場所は rekordbox 側（取り込みがマージなので打ち直せる）。
**古い「イントロ 89% / メイン 68%」を引用しないこと** — 物差しの欠陥で水増しされた数字。

測り直すとき:

```bash
node scripts/cue/eval.js --show 0     # 174 曲 / 約 55 秒。耳も rekordbox も要らない
node scripts/cue/style.js             # 本人の流儀（Ｑの数・間隔・連）。音源を読まないので 1 秒
```

## 中身

| | |
|---|---|
| `src/features.js` | 音源 → 小節ごとの帯域エネルギー。グリッドは rekordbox の `<TEMPO>` をそのまま使う。`trueTempos()` が倍/半分を直す |
| `src/detect.js` | 小節の特徴量 → 各点の小節番号。**アウトロを先に決めてからメインを探す**（順番を変えると終盤を掴む）。位相は音から当てず rekordbox の小節線に乗せる |
| `src/collection.js` | `collection.xml` を**読む**層。引き当ては `Size` + basename |
| `src/cues.js` | 1 曲ぶんのＱを決める。同じ小節に重なったら名前を合わせて 1 本にする |
| `src/xml.js` | Ｑ入り XML を書く。**写して挿すだけ** |
| `src/cli.js` | 入口 |
| `test/run.js` | 検査。A = 音源不要 / B = 実音源の回帰（**本人の 5 本を全部含むか**。本数の完全一致は見ない） |

`scripts/cue/` に残っているもの: `eval.js`（物差し）/ `gate-xml.js`・`gate2-newtrack.js`（通したゲートの材料）。
どれも `packages/cuetool/src/` から import している。

## 試して却下した案（蒸し返さないため。実測つき）

- **曲の頭から終わりまで 8 小節ごとの梯子を出す**（2026-10-17 案）→ ユーザーが実機で
  9/25/33/89 小節のＱを消した。多すぎる。**ただし「盛り上がりの中だけ」は本人もやっている**
  （2026-10-21 に実測。8 小節の連が 1 曲 2.02 本）。**どこに刻むかが本質で、刻むこと自体は正しい**
- **「始まり」をイントロ終わりの 8 小節あとから探す** → 一致が **53% → 45%** に落ちた
  （2026-10-20。重なる小節はたいてい当たっている。同じ小節なら名前を合わせる方が正しい）
- **メインをアウトロより後ろまで探す** → 終盤の一番濃い所を掴み、**アウトロと同じ小節にメインが立った**
  （2026-10-21 実測: Don't Lose Your Head で 105 小節）。**アウトロを先に決めて範囲を切る**
- **`AverageBpm` / `<TEMPO>` を属性ごと消す** → 無い TRACK を rekordbox がどう扱うか未確認。
  **写して書き戻す方が安全で、ゲートを通した形のまま**
- **`features.db` の特徴量を使う** → `EXCERPT_SEC=60` の 1 窓だけで曲頭も終わりも入っていない
- **master.db を直接書く / ANLZ を書く / m3u8 で渡す / 曲を複製する** → 取り込みゲートが通ったので全部不要
